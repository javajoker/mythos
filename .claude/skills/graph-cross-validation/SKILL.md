# 圖譜交叉驗證與衝突裁決 / Graph cross-validation

## 檢查維度

1. **文本與抽取**：逐字引文、讀法狀態、提及覆蓋、比喻與關係偽影。
2. **推論順序**：是否先取原文、靜態形狀和物理特徵，再按古代通用詞義比較同時代候選。
3. **靜態形狀與拓撲**：輪廓、相對位置、連接、環繞、包含、分支與分佈是否一致。
4. **空間與水文**：發源、注入、相鄰、相對幾何、跨篇連接證據與未錨定項；動態流向與現代水流不得單獨否決。
5. **因果與詞義**：是否以後世地名、現代分類或狹窄物種差異倒置因果，或只對偏好候選使用詞義寬容。
6. **文化歷史斷層**：傳播鏈缺失只能標為未知；不得編造機制，也不得作為正反證。
7. **距離與比例尺**：在語料允許區間做敏感度，不把單一數值吻合當證明。
8. **考古、古環境與對立組態**：候選年代、當時形態、生態是否相容；固定假說後與競爭組態重解比較。
9. **地理映射完整性**：全部 MTN/WAT/LND 是否逐子經整包由 LLM 映射並由發起人確認；共享水是否保留為單一候選；改道、消亡、人工渠道與沼澤化是否納入競爭狀態；水名按 ADJ-005 性狀類名處理（多實例合法）。
10. **語義指稱範圍**：共享詞根的山丘、山脈、窪地、遺址、河段與支流是否被錯誤合併；聯動配置是否讓每個組成部分仍保留獨立候選與反例。

## 衝突處理

程序只負責 schema、引用、數值、覆蓋和衝突發現。LLM 裁決必須：

1. 列出衝突實體、屬性、原文、候選值和對立解釋。
2. 檢查至少一項反向證據或競爭候選。
3. 選擇 `merge`、`split`、`accept_variant`、`keep_both`、`revise` 或 `unresolved`，並附理由。
4. 記錄模型、提示版本、輸入雜湊、審核狀態和精確更新範圍。
5. 回寫受影響圖譜與指定草稿，重跑相關校驗；不得用程序啟發式自動選答案。

人工覆核高於 LLM。所有裁決寫入機器可讀記錄與 `findings/conflict-resolutions.md`。
