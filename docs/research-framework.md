# Mythos 研究框架 v4：迭代時代語義對應 / Iterative Era-Semantic Correspondence

> v4.0 · 2026-10-21 · 公共方法；山海經的專用設定見 [methodology-spec.md](../projects/shanhaijing/docs/methodology-spec.md)。
> Public method only. Corpus-specific constraints belong to the corpus specification.

## 1. 立場 / Stance

古籍、神話與傳說可能保存真實觀測，也可能包含想像、修辭與傳抄錯誤。Mythos 不預設哪一種解讀正確，而是把文本中的實體、描述和關係，與其時代世界中的競爭候選逐項比較，保留可追溯的證據、反例與不確定性。

Ancient texts are treated as transmitted records, not as predetermined answers. Every correspondence remains a falsifiable hypothesis until it survives evidence, rival-candidate and red-team review.

## 2. 四個資料層 / Four data layers

| 層 / Layer | 內容 / Content | 不得混入 / Must not contain |
|---|---|---|
| 原文層 / Source | 見證本、條目、異文、工作文本與讀法裁決 | 任何現實地理解讀 |
| 文本事實圖 / Text graph | 實體、提及、名稱語義、文本明示關係 | 未標示的現代坐標或候選結論 |
| 解釋圖 / Interpretation graph | 語義擬合、時代候選、聯想與演繹屬性、可信度 | 與原文事實混為一談的斷言 |
| 交付層 / Deliverables | 草稿、對照表、衝突日誌、地圖與審查報告 | 高於證據等級的確定性措辭 |

## 3. 迭代流程 / Iterative pipeline

公共流程如下；各語料可定義底層卷冊與後續卷冊。/ The corpus specification defines base and extension sections.

1. **建立工作文本**：固定條目 ID，校勘見證本，分離主文、注疏與異文，記錄讀法狀態。
2. **實體抽取**：從工作文本抽取實體、提及、名稱語義和文本關係；允許未定類型與未決提及。
3. **地理語義擬合**：在名稱遮蔽下提出競爭候選，逐屬性形成地理、時代與物理屬性判斷。
4. **形成初版圖譜**：合併文本事實與有來源的語義擬合屬性，不把候選寫成既定事實。
5. **完成底層卷冊草稿**：逐條引用原文，區分文本事實、候選解釋和未決項。
6. **補充屬性圖譜**：加入聯想性與演繹性屬性，並標明它們不是原文直接陳述。
7. **完成後續卷冊**：按語料規則復用或新增實體，更新文本圖與解釋圖。
8. **語義衝突解決與合併**：程序發現與計算，LLM 依證據裁決；必要時回寫指定條目和圖譜。
9. **迭代**：重跑受影響的抽取、評分、草稿和圖譜，直到完整性檢查通過且沒有未處理的阻斷衝突。
10. **紅隊與交付**：檢查對立候選、洩漏、年代、敏感度與措辭，再生成對照表和示意地圖。

## 4. 核心原則 / Principles

| # | 原則 / Principle |
|---|---|
| P1 | **原文為準**：每個實體、屬性和關係都可回到條目 ID 與逐字引文；注疏不作為原文證據。 |
| P2 | **競爭假說**：任何現實對應都必須與至少兩個其他可行候選比較，不得因預設地區或名氣直接勝出。 |
| P3 | **時代世界**：候選附年代、當時狀態和一般性來源；時代窗口外的事物不得作為同時候選。 |
| P4 | **逐屬性有據**：外觀、顏色、尺度、材質、功能、聲音、生態、方位和年代分別記錄證據與理由。 |
| P5 | **名稱語義而非今名**：名稱只提供低權重語義特徵；今名相似不是證據。 |
| P6 | **有限傳抄容錯**：缺失不自動等於矛盾；替代讀法須有見證本或明確錯誤類型，並留下裁決記錄。 |
| P7 | **關係優先於孤立相似**：全書的水系、相對位置與共現關係是主要一致性約束。 |
| P8 | **全球對稱**：同類候選使用相同資料詳度、容錯和評分規則。 |
| P9 | **分層與可擴展**：文本屬性、語義擬合、聯想和演繹分開；新屬性透過註冊 predicate 擴展，不改寫歷史事實。 |
| P10 | **可審查的 LLM 推理**：保留模型、提示版本、輸入雜湊、樣本、證據和理由；輸入不變不重判。 |
| P11 | **可信度誠實**：對立候選、穩定度、敏感度、洩漏和紅隊結果決定措辭；暫定不得寫成定論。 |
| P12 | **可重現**：來源有快照與雜湊，工具輸出確定性排序，生成物可由同一輸入重建。 |

## 5. 解讀規則 R1–R15 / Reading rules

| # | 規則 / Rule |
|---|---|
| R1 | 河、水、海、澤先只視為水體，類型由證據決定。 |
| R2 | 已消失、已改道或已成遺跡的地物可作時代候選。 |
| R3 | 「山」先視為外觀描述；自然山或人工高台均為競爭類型。 |
| R4 | 描述可按外觀或效果吻合，但須說明轉譯步驟。 |
| R5 | 方位慣例可作候選模型，所有候選使用相同替代慣例。 |
| R6 | 「出、流、注」可先表示圖上線條；若解讀為實際水源與流向，須另有證據。 |
| R7 | 觀察者可能以熟悉事物描述陌生事物；替代關係須標為假說。 |
| R8 | 長時代窗口中的不同段落可能來自不同時期，候選須標存在年代。 |
| R9 | 觀察原點由可共同確認的地標與關係反推；共識形成後以穩定 ID 登記，不用含混城市名代替。 |
| R10 | 古名與今名脫鉤；同名不必然同物，異名不必然異物。 |
| R11 | 形近、數字、漏簡與錯簡只形成讀法候選；程序報告差異，LLM 或人類依證據裁決。 |
| R12 | 天象、地質與感官轉譯可作候選解釋，不得跳過對立候選。 |
| R13 | 古環境反推只在對應經獨立驗證後進行，不能用反推結果循環證明原對應。 |
| R14 | 各篇先獨立建模；跨篇連接必須有文本或已接受關係證據。里程總和不是天然的地理跨度，比例尺只在語料指定區間內擬合。 |
| R15 | 同名實體的遠距拆分、近距合併與爭議保留均由 LLM 結合距離和關係裁決；語料的第一版硬約束只限制可用節點，不指定現實答案。 |

## 6. 程序與 LLM 的職責 / Code versus LLM

**程序負責**：快照與雜湊、格式與引用校驗、文本定位、可重現的數值計算、覆蓋檢查、候選衝突發現、執行已記錄的結構變更。

**LLM 負責**：實體與屬性語義抽取、候選生成、逐項評分、異文與關係的語義裁決、同名合併或拆分、解釋衝突處理、指定草稿修訂。裁決必須附證據與理由；程序不得用相似度閾值或硬編碼答案代替裁決。

## 7. 審查與交付 / Review and delivery

- 每個判斷至少三個樣本；候選順序打亂，並記錄輸入雜湊。
- 抽樣進行不遮蔽洩漏探測與誘餌測試；紅隊同時攻擊支持與反對候選。
- 完整性只表示覆蓋，不表示解釋正確；所有未抽取、未對應與未決項必須顯式列出。
- 地圖只從目前有效的圖譜與時代資料生成，並標示假說、可信度和簡化輪廓。
