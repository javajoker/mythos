# Mythos 產品需求文件（PRD）

> 版本 3.0 ・ 2026-10-20 ・ [English](prd.en.md)

## 1. 背景與目標

Mythos 的「產品」有三部分：方法（時代語義對應，框架 v3）、可重現的研究資料庫（原始文本、知識圖譜、當時世界、判斷紀錄），以及一組 AI 研究代理。目標是讓任何人都能重新產生、檢查、挑戰一部古籍對應到其時代世界的完整逐條對照。

| 目標 | 指標 |
|---|---|
| G1 不遺漏 | 交付涵蓋 100% 的段落與實體提及；未對應的寫明原因 |
| G2 可追溯 | 每個實體、關係、判斷、對應都連回條目編號與原句 |
| G3 不繼承結論 | 注疏與前人學說不作為輸入；判斷在遮蔽下進行；測量洩漏 |
| G4 合乎時代 | 每個候選在時代窗口內存在或可見，附年代與當時樣貌 |
| G5 可信度誠實 | 每個對應附可信度、級別、證據與對立候選 |
| G6 可重現 | 工具輸出逐位元組相同；判斷有紀錄，輸入不變不重判 |
| G7 可擴充、多語 | 新語料只需入庫、實體句式與時代窗口三個設定；每加一種語言就加一個文檔版本 |

## 2. 使用者

| 角色 | 需求 |
|---|---|
| 研究者（人）| 閱讀對應、詢問「X 在哪裡」、提出解讀並看它與對立解讀一起檢驗 |
| AI 研究代理 | 建立時代世界、在遮蔽下判斷候選、求解、交付 |
| 審查者／紅隊 | 找洩漏、誘餌失敗、今名比對、不對稱、年代錯誤 |
| 讀者 | 連同可信度與限制閱讀對應與當時地圖 |

## 3. 範圍（第一階段：山海經時代語義版）

### 3.1 必須（P0）
- **R1** 原始文本：三個見證本、869 段、明成化本次序；注疏不進入分析。✅
- **R2** 全書知識圖譜，覆蓋檢查未解釋為零。✅
- **R3** 每個實體的名稱特徵（顏色、材質、形狀、狀態、方位）。
- **R4** 以中原為原點的觀察框架，方位與里程為軟約束。
- **R5** 前 4000–前 2000 年的時代世界庫：遺址與造物（以兩河流域、哈拉帕、古埃及為重點，同時期文明為對立候選）、水體、含已滅絕者的動物、人群、當時的海岸線。
- **R6** 遮蔽下的語義判斷，附證據、理由與三個樣本；洩漏探測與誘餌。
- **R7** 以判斷為分數的聯合求解與可信度；解讀以固定組態檢驗。
- **R8** 交付 draft-v4：每一段、每個實體，加上當時地圖，附完整性檢查。

### 3.2 應該（P1）
- **R9** 先以西山經四篇與大荒西經試點，再擴及全書。
- **R10** 每一版的權重敏感度與紅隊審查。

### 3.3 可以（P2）
- **R11** 當時世界的互動地圖。
- **R12** 跨語料圖譜（穆天子傳、淮南子・地形訓、禹貢、水經）。

## 4. 功能需求

| ID | 需求 | 驗收 |
|---|---|---|
| F1 | 文本層 | `ingest.py` … `extract_routes.py` 產生條目、工作文本、異文、站點 |
| F2 | 知識圖譜 | `kg_extract.py`：無實體段落 0、未解釋的名稱句式 0、名稱特徵齊全 |
| F3 | 時代世界庫 | `data/era/` 每張卡有年代、樣貌與一般性來源；計分前提交 |
| F4 | 判斷 | 每筆紀錄有遮蔽輸入的雜湊、模型、提示詞版本、樣本序號、逐維度證據與理由 |
| F5 | 求解 | `era_solve.py` 寫出附可信度、級別、證據與對立候選的對應；兩次執行相同 |
| F6 | 交付 | `era_deliver.py` 寫入的段落數與提及數不等於原書就失敗；畫出當時地圖 |

## 5. 非功能需求
- 可重現：Python 標準庫、`python3 -I`、固定種子、輸出排序；判斷以輸入雜湊快取。
- 中立：不預設地區；每種寬容與每類候選一體適用；每個比較都有對立候選。
- 授權：程式與文檔 Apache-2.0；古籍為公有領域；維基文庫轉錄依 CC BY-SA 4.0。

## 7. 風險

| 風險 | 對策 |
|---|---|
| 模型的先入知識左右判斷 | 遮蔽、不遮蔽探測、誘餌、對立候選；洩漏折扣可信度 |
| 語義比對什麼都能套上 | 罕見度加權、矛盾有上限、跨關係聯合求解、固定組態檢驗 |
| 庫偏向資料詳細的地區或重點文明 | 對稱規則、對立候選、每次審查的平衡檢查 |
| 年代或當時樣貌錯誤 | 每張卡附年代；窗口外的候選排除 |
| 過度解讀弱結果 | 處處標級別；暫定不引用 |
